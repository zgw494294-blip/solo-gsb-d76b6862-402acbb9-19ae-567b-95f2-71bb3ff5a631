# 步道坡线规划台

本地运行的步道纵坡规划小工具：在网页上编辑等间距（1 m）测点的地面标高
并输入步道净宽，后端用 Python / FastAPI 计算满足坡度与水平段约束的最优
方案标高，页面叠画地面坡线与方案坡线，并列出每段高差、水平段、总调整量
以及土方调配核算（分段挖填、累计净量、调配流向与运量距离）。

- 前端：原生 HTML / CSS / JavaScript（Canvas 绘图，无框架、无构建步骤）
- 后端：Python + FastAPI，动态规划求最优解

## 一条命令启动

需要已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build
```

启动后浏览器访问：

```
http://localhost:8000
```

端口为 **8000**（容器内 `8000` 映射到宿主机 `8000`，见 `docker-compose.yml`）。
后台运行可加 `-d`，停止用 `docker compose down`。

## 不使用 Docker 的本地启动方式

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问地址同样为 <http://localhost:8000>。

## 规划规则

| 项目 | 规则 |
| --- | --- |
| 测点数量 | 3～16 个，等间距 1 m |
| 地面标高 | 0～200 的整数厘米 |
| 方案标高 | 0～200 的整数厘米 |
| 首尾约束 | 方案首、尾标高必须分别等于地面首、尾标高 |
| 相邻高差 | 相邻方案点高差绝对值 ≤ 8 cm |
| 水平段要求 | 任意连续 5 段中至少有 1 段水平段（相邻方案标高相等） |
| 步道净宽 | 0.5～10 米，最多两位小数（土方核算用） |
| 优化目标 | 总调整量 Σ\|方案标高 − 地面标高\| 最小 |
| 同分裁决 | 取方案标高序列字典序最小者 |

测点不足 6 个（少于 5 段）时，“任意连续 5 段”约束自动不触发。

## 页面与接口说明

- 顶部表格编辑各测点地面标高，可增删测点（受 3～16 个限制）；
  首尾测点的方案标高固定等于地面标高。修改后自动重新计算。
- 图中：**棕色虚线**为地面坡线，**绿色实线**为方案坡线，
  水平段在方案线上以**蓝色点划**叠加标出。
- 结果区列出各点地面/方案标高及差值、各段高差（正为抬升、负为下降）、
  水平段标记、水平段数量、最大相邻高差与总调整量。
- **土方调配核算**：输入步道净宽后随方案一同更新，列出每段挖方、填方、
  段净量与段后累计净量，以及起点至首段中点、相邻中点间的有向净流量与
  运量距离；测点或净宽变化时自动重算，非法输入或无解时清除旧核算。
- 非法输入（数量越界、非整数、超出 0～200、净宽越界或小数位过多等）或
  问题无解时，页面以提示条给出中文原因；无解时会区分“坡度约束本身不
  可达”（含首尾高差超限说明）与“水平段约束无法同时满足”。

HTTP 接口（也可直接调用），请求体需同时给出 `ground`（地面标高，整数
厘米）与 `width`（步道净宽，米）：

```bash
curl -X POST http://localhost:8000/api/plan \
  -H 'Content-Type: application/json' \
  -d '{"ground":[100,107,114,119,124,130],"width":2.0}'
```

返回示例（`earthwork` 节选，体积均为米³，全程不提前取整）：

```json
{
  "feasible": true,
  "ground": [100, 107, 114, 119, 124, 130],
  "plan": [100, 107, 114, 122, 122, 130],
  "total_adjustment": 5,
  "segments": [ {"index": 1, "from": 1, "to": 2, "delta": 7, "horizontal": false} ],
  "horizontal_indices": [4],
  "earthwork": {
    "width": 2.0,
    "unit": "m3",
    "total_cut": 0.00048,
    "total_fill": 0.00028,
    "total_net": 0.0002,
    "segments": [
      {"index": 3, "from": 3, "to": 4,
       "cut": 0.0003, "fill": 0.0, "net": 0.0003}
    ],
    "cumulative_net": [0.0, 0.0, 0.0003, 0.0004, 0.0002],
    "flows": [
      {"index": 1, "from": "起点", "to": "段1中点",
       "flow": -0.0002, "distance": 0.5},
      {"index": 2, "from": "段1中点", "to": "段2中点",
       "flow": -0.0002, "distance": 1.0}
    ],
    "haul_distance": 0.0008,
    "haul_unit": "m3·m"
  }
}
```

字段含义：

- `segments`：各段挖方 `cut`、填方 `fill` 与段净量 `net = cut − fill`
  （正为净余、负为净缺）；`cumulative_net` 为逐段后累计净量。
- `flows`：调配边上的有向净流量，**正值朝终点、负值朝起点**；第 1 条边为
  起点→段1中点（距离 0.5 m），其余为相邻段中点之间（距离 1 m）。
  全线净余经起点运出（首边流量为负），净缺由起点运入（首边流量为正）。
- `haul_distance`：运量距离 Σ|流量|×距离（m³·m）。

调用约定：

- `200` 且 `feasible=true`：返回 `plan`、`segments`、`horizontal_indices`、
  `total_adjustment` 与 `earthwork` 核算结果。
- `200` 且 `feasible=false`：输入合法但无可行方案，`reason` 说明原因，
  不返回 `earthwork`。
- `400`：请求体不是合法 JSON，或缺少 `ground` / `width` 字段。
- `422`：输入非法（标高数量/类型/取值范围，或净宽不是数字、超出
  0.5～10、小数位多于 2 位），`reason` 说明原因。

## 土方调配核算口径

- 每段（长 1 m）地面与方案标高均按端点**线性变化**，分别积分挖方与
  填方：高差函数同号时取梯形面积，段内由挖变填（或反之）时在交点拆成
  两个三角形分别积分；标高由厘米换算为米，体积 = 截面积 × 步道净宽，
  以立方米计。
- 同段挖方与填方先在段内抵消，余量（段净量）视为集中在**该段中点**。
- 余量只允许沿“起点—首段中点—…—末段中点”相邻节点调配，全线净余或
  净缺只经**起点**进出；由各中点守恒可唯一确定每条边的有向净流量，
  最后一个中点之后（终点方向）不进出。
- 计算全程使用浮点精度、不提前取整；页面对展示值保留三位小数。

## 算法

带“最近 4 段是否水平”位掩码状态的动态规划：

- 状态 `dp[pos][mask][h]`：第 `pos` 点方案标高取 `h`，`mask` 打包此前
  最近 4 段是否水平时，后缀（含本点）的最小调整量；
- 转移枚举下一标高（高差 ≤ 8），当放下的段构成完整的连续 5 段窗口时，
  要求窗口中至少一个水平位；起点之前的“虚拟段”视为水平，
  使不足 5 段时不误触发约束；
- 重建最优路径时每点自低到高取第一个可行且仍为最优的标高，
  即得到同分下字典序最小的方案。

16 个测点的最坏规模单次计算约 0.1 秒（纯 Python）。

### 土方调配

- 段内高差 `d(x) = 方案(x) − 地面(x)`（正为挖、负为填）在线性变化下，
  同号取梯形积分；变号时求交点 `x = d0/(d0−d1)` 拆成两个三角形分别
  积分，再乘净宽并由厘米²换算为米³。
- 各段净量集中于段中点（坐标 i−0.5）。调配网络为“起点(0) → 中点(0.5)
  → 中点(1.5) → …”的一条链，全线净余/净缺只能在起点进出；设全线净量
  为 `T`、前 k 段累计净量为 `C[k]`，则起点边流量 `f0 = −T`，
  第 k 条中点边（k ≥ 1）流量 `f[k] = −T + C[k−1]`，即前缀累计唯一确定，
  天然满足每个中点的土方守恒。运量距离为 `Σ|f|·L`（首边长 0.5 m，
  其余边长 1 m）。
